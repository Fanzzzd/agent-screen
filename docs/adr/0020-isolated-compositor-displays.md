# Each Linux Agent Display runs an isolated headless Wayland compositor

Accepted, 2026-11-16.

On Linux, Wayland compositors bind pointer and keyboard injection (`libei`, RemoteDesktop portals) to the host desktop's logical `wl_seat`. Moving a pointer or focusing a window on a virtual output of GNOME Mutter, KDE KWin, or Hyprland moves the user's real cursor and steals focus, breaking ADR 0001. Pure Xvfb misses Wayland-native GTK4 and modern desktop apps.

Agent Screen therefore runs each Linux Agent Display inside its own `systemd --user` transient scope (`agent-screen-display-<id>.scope`), holding a dedicated headless Wayland compositor (`sway` first, replaceable behind the `Display` port by an out-of-process `Smithay` worker), an on-demand rootless `Xwayland` instance, a private session `dbus-daemon`, and a private AT-SPI2 `dbus-daemon` with `at-spi2-registryd`.

## Isolation rules verified on hardware

Measured on Omarchy 4.0.1 (Linux 7.1.9, Hyprland 0.56.2 on `wayland-1`, `dbus-broker`, `at-spi2-core` 2.60.6, `sway` 1.12, GTK 4.22.4, Qt 6.11.2, Chromium, `docs/prototypes/linux-compositor-spike`):

- **Per-display `XDG_RUNTIME_DIR`**. Each display scope sets `XDG_RUNTIME_DIR` to a mode `0700` directory under `$XDG_RUNTIME_DIR/agent-screen/displays/<id>/runtime`. On Hyprland, the host compositor binds `/run/user/<uid>/wayland-1` and leaves `wayland-0` free; sharing `/run/user/<uid>` would let headless `sway` claim `wayland-0`, the default socket `libwayland-client` opens when `WAYLAND_DISPLAY` is unset. A dedicated `XDG_RUNTIME_DIR` keeps the display's `wayland-1`, `sway-ipc.sock`, `session-bus.sock`, and `atspi-bus.sock` out of `/run/user/<uid>`.
- **Daemon crash survival and adoption**. The daemon starts each scope with `systemd-run --user --scope --collect`, never sets `PR_SET_PDEATHSIG`, and writes `state.json` atomically (`532.8 ms` cold start). After `SIGKILL` to the daemon, the scope, `sway`, `Xwayland`, both `dbus-daemon` buses, `at-spi2-registryd`, and launched apps stay alive with the same PIDs. A restarted daemon scans surviving scopes and rebinds handles when the MCP server sends `adoptGroups` in `createDisplay` (ADR 0016), or turns unclaimed non-empty scopes into Review Displays. Environments without a user systemd bus fall back to `setsid` process groups and PID files.
- **Capture, virtual seat, and clipboard**. The daemon captures frames over `wlr-screencopy-unstable-v1` (`39.7 ms` initial, `23.4 ms` subsequent at `1280x800`) and drives input through `wlr-virtual-pointer-unstable-v1` and `virtual-keyboard-unstable-v1` with dynamic XKB Unicode keymaps. Because each compositor owns a private `wl_seat`, `ctrl+c`, `ctrl+v`, `ctrl+z`, and pointer drags work inside the display while the host Hyprland cursor and active window never move. Display clipboards stay isolated from the host during agent work; `wlr-data-control-unstable-v1` bridges text and images only while the user holds focus in a Viewer Takeover.
- **AT-SPI2 under `dbus-broker` and Xwayland**. `at-spi-bus-launcher` unlinks `$XDG_RUNTIME_DIR/at-spi/bus*` under `dbus-broker` and skips setting the X11 `AT_SPI_BUS` root window property whenever `WAYLAND_DISPLAY` is set (`at-spi-bus-launcher.c`). Agent Screen clears inherited `AT_SPI_BUS_ADDRESS`, runs a dedicated `dbus-daemon` and `at-spi2-registryd` on `atspi-bus.sock`, and writes `AT_SPI_BUS` (`STRING`) to the display's Xwayland root window via X11 `ChangeProperty` followed by `sync` before closing the X11 connection. Without that root property, X11 Qt6 clients with `AT_SPI_BUS_ADDRESS` unset miss the private bus; with it, GTK4 Wayland, Qt6 Wayland, Qt6 Xwayland, and Chromium (`--force-renderer-accessibility`, `387.2 ms` to 238 nodes) all register on `atspi-bus.sock` while host `/run/user/<uid>/at-spi/bus_0` keeps its inode and receives zero events.
- **Password field role check**. For ADR 0014 Viewer key privacy, `GetRoleName()` returns `"password text"` in Chromium, `"text box"` in GTK 4.22, and `"text"` in Qt 6.11, whereas numeric `GetRole()` returns `40` (`ATSPI_ROLE_PASSWORD_TEXT`; `39` is `ATSPI_ROLE_PANEL`) in all four targets. Linux `focus_secrecy` therefore checks `GetRole() == 40` first and treats `"password text"` only as a secondary match.
- **Private D-Bus compensations**. Both private `dbus-daemon` configs omit `<standard_session_servicedirs/>`, so apps inside the display cannot activate host systemd services, keyrings, or XDG portals; calls to `org.freedesktop.secrets` and `org.freedesktop.portal.Desktop` fail in `0.2 ms` instead of waiting 25 seconds for activation timeouts. The daemon serves a silent `org.freedesktop.Notifications` receiver on `session-bus.sock` (`0.8 ms` reply), injects `GTK_USE_PORTAL=0` for in-window file dialogs, and launches Chromium and Electron apps on isolated `0700` profiles with `--password-store=basic`.

## Display-bound window model

A Wayland client connects to one compositor socket at startup and cannot migrate an open surface to another compositor. Five macOS behaviors change on Linux:

1. **No host Handover or Window Authorization** (`CONTEXT.md`, ADR 0013, ADR 0015). Existing windows on the host desktop cannot move onto an Agent Display. `agentReady` omits `host_window_handover`, `AgentScreen mcp` hides `window_access`, and Help Requests offer `Take Over`, `Continue`, and `Reply` without `Give`. Users sign in once through a Viewer Takeover on the agent's isolated browser profile.
2. **No cross-display or cross-session window moves** (ADR 0016, ADR 0017). A session can still hold up to four Agent Displays, but every window stays on the display where `launch_app` started it. `place_window` resizes and moves windows within their own display and rejects cross-display or cross-session targets.
3. **Inherent window ownership** (ADR 0018). Every window connected to display `<id>`'s compositor belongs to display `<id>` with `Origin::Launched`. No global coordinate arrangement or `claims.json` tracking applies.
4. **Review Display keep semantics** (ADR 0004). When a session ends with windows left on a display, the display becomes a Review Display and rejects further agent input. Because windows cannot move to the host compositor, `Disposition::Keep` keeps the Review Display scope running so the user can inspect, copy, or save work in the Viewer or Web Preview; the scope stops only when its windows close or the user confirms closing all windows and dismissing the display.
5. **No Input Queue or Keyboard Borrow** (ADR 0008, ADR 0013). Each display has its own focused seat and XKB keymap, so `AgentScreen mcp` omits `input_queue`, `real_input`, `via_input_method`, and `input_source` when talking to the Linux daemon.
