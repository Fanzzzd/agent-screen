# AeroSpace leaves Agent Displays alone, through upstream or our fork

Stock AeroSpace manages every display, virtual ones included. It shows one of the user's workspaces on each new Agent Display, which takes the user's windows off their screen and into the agent's screenshots, and it files every new window in the user's focused workspace, so a window an agent launches flashes on the user's screen and their tiled windows reflow around it. Agent Screen can only repair this after the fact: its guard moves workspaces back and it moves new windows the moment AeroSpace registers them, which shortens the damage to a frame or two but never removes it, and guessing wrong moved workspaces between the user's monitors. So the fix belongs in AeroSpace: an `ignored-monitors` option (`ignored-monitors = ['^Agent Screen']`) under which AeroSpace neither assigns workspaces to matching monitors nor manages windows on them.

We proposed it upstream first, in [Discussion #2305](https://github.com/nikitabobko/AeroSpace/discussions/2305) and [PR #2306](https://github.com/nikitabobko/AeroSpace/pull/2306) on 2026-10-01. If no maintainer answers by 2026-10-15, or they decline, we recommend our fork instead: `Fanzzzd/AeroSpace`, branch `sidescreen`, a drop-in replacement with the same bundle id and app name, signed with our Developer ID, installed from the `fanzzzd/agent-screen` tap as `aerospace-sidescreen`. It follows upstream releases, with a weekly job that rebases the patch, builds and tests, and opens an issue instead of releasing when that fails. We don't rewrite AeroSpace: the patch is under 200 lines against 21,000, and AeroSpace's worth is its years of per-app window handling.

Agent Screen keeps its guard for users on stock AeroSpace without `ignored-monitors`, and offers, from the menu, to add the option to their config, asking first and keeping a backup. A config that ignores `^Sidescreen`, the app's former display names, gets `^Agent Screen` added beside it at launch without asking: the user already chose to ignore these displays. Refusing to run under stock AeroSpace would turn most of its users away on first launch; doing nothing would show their windows to agents.
