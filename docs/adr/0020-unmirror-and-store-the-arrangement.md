# A mirrored new display is unmirrored and its arrangement stored

When WindowServer adds a display, it looks for a stored arrangement for the new set of displays. WindowServer keeps one arrangement per set of display identities, the last one stored, and applies it only while each display can run at its stored size ("validation: no available match for persisted mode" otherwise). On 2026-11-18 its plist held 851 arrangements of 851 sets. A set with no fitting arrangement gets WindowServer's default. On the Mac of #220 that default changed on 2026-11-17 at 17:05, after a mirror was chosen in System Settings. From then on it mirrored the built-in display onto any new display and made the new display main. A mirrored built-in display runs at the new display's size, so the user's screen changes resolution. A set with a stored arrangement never mirrored: at 13:38 on 2026-11-18, serial 3 came up parked at 1728,-2400, where it had been before.

0.1.39 released such a display at once and refused new displays for 30 minutes. The display went before WindowServer stored anything, so its set never got an arrangement, and every attempt with that set mirrored again.

Now a new display that lands on the user's screen (`landing::landing`) comes out of its mirror set, and so does each user display that mirrored a new display. A mirror the user chose before, such as the built-in display shown on a projector, stays: it is set again where macOS moved it under a new display. Each user display that mirrored none gets back its earlier origin and mode, and the new display is parked by `arrangement::plan` (`landing::unmirror_plan`, from each user display's origin, mirror and mode taken before the display was made). All of that happens in one display configuration, completed with `kCGConfigurePermanently`; a configuration WindowServer refuses goes straight to the release below. WindowServer stores that arrangement for the set, and Agent Screen keeps the display. The user's screen flashes once per set and size: 0.79, 1.52 and 1.18 s from mirror to the built-in display's own mode in three runs on 2026-11-18. About 0.35 s of that passes before the app has the display. The next display of that size in that set lands parked. `arrangements.json` in `~/Library/Application Support/Agent Screen/`, shared by all instances, records each set the app stored (`landing::StoredSets`).

The 0.1.39 release and refusal stay as a backstop (`landing::OnLanding::Release`). Agent Screen falls back to them when WindowServer refuses the change, when the mirror isn't off within 8 seconds, when the mirror returns while the display is parking, when the very arrangement it stored less than 30 minutes ago mirrors again, when it unmirrored the same set twice in 30 minutes at any sizes (`landing::UNMIRRORS_PER_SET`), since sizes in turn would replace the set's one arrangement and flash at every creation, or when this is the instance's third display on the user's screen in 30 minutes, at any sets (`landing::RecentMirrors`, in `mirrors.json`, per instance), since each size has its own set and many new sizes would each flash once. Forgetting a set doesn't reset that count; Allow New Displays does. In that last case it drops the set's entry, so after the refusal ends it tries unmirroring again. If WindowServer ignores stored arrangements, this costs at most one flash per refusal, as in 0.1.39.

A set that mirrors again at another size is unmirrored like a new one: `landing::StoredSets` keeps one arrangement per set, as WindowServer does (`landing::display_set`). 0.1.40 keyed it by identity and size, so at 16:44 on 2026-11-18 it took a 1280x800 display whose set had been stored at 1200x800 and 1152x800 since for a stored arrangement failing, released it and refused new displays for 30 minutes. The refusal is also per instance now (`bad-units-<instance>.json`): an e2e instance's refusal had refused the user's agents too. Another instance's landing gets its own unmirror first, so sharing protected nothing.

Each size gets its own serial, so its own set of displays: of 8 serials per instance, the one last leased at that size (`model::SerialSizes`, in `serials.json`). The lowest free serial, as before, gave one serial every size, and agents ask for many sizes (serial 10001 ran at 1280x800, 1600x1000, 1100x700, 1728x1117 and 900x600 within minutes on 2026-11-18). This costs up to 8 ColorSync records per instance instead of one per display held at once (ADR 0009 keeps the first 16), and a new size past 8 takes the serial leased longest ago, whose size flashes once more. A second display of a size held already, such as a second spare of the default size, takes one past the 8 instead, so it doesn't push out a size agents use.

Mode changes and ordinary parking still complete for the session only. Made permanent while a mirror is on, they would store the mirror. Only the change that turns the mirror off is stored.
