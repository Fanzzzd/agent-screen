# A mirrored new display is unmirrored and its arrangement stored

When WindowServer adds a display, it looks for a stored arrangement for the new set of displays. An arrangement is keyed by each display's identity and must fit each display's current size ("validation: no available match for persisted mode" otherwise). A set with no fitting arrangement gets WindowServer's default. On the Mac of #220 that default changed on 2026-11-17 at 17:05, after a mirror was chosen in System Settings. From then on it mirrored the built-in display onto any new display and made the new display main. A mirrored built-in display runs at the new display's size, so the user's screen changes resolution. A set with a stored arrangement never mirrored: at 13:38 on 2026-11-18, serial 3 came up parked at 1728,-2400, where it had been before.

0.1.39 released such a display at once and refused new displays for 30 minutes. The display went before WindowServer stored anything, so its set never got an arrangement, and every attempt with that set mirrored again.

Now a new display that lands on the user's screen (`landing::landing`) has its mirror turned off, the user's displays put back at their earlier origins, and itself parked by `arrangement::plan`. All of that happens in one display configuration, completed with `kCGConfigurePermanently`. WindowServer stores that arrangement for the set, and Agent Screen keeps the display. The user's screen flashes once per set and size: 0.79, 1.52 and 1.18 s from mirror to the built-in display's own mode in three runs on 2026-11-18. About 0.35 s of that passes before the app has the display. The next display of that size in that set lands parked. `arrangements.json` in `~/Library/Application Support/Agent Screen/`, shared by all instances, records each set the app stored (`landing::StoredSets`).

The 0.1.39 release and refusal stay as a backstop (`landing::OnLanding::Release`). Agent Screen falls back to them when the mirror isn't off within 8 seconds, when the mirror returns while the display is parking, or when a set it stored mirrors again. In that last case it drops the set's entry, so after the refusal ends it tries unmirroring again. If WindowServer ignores stored arrangements, this costs at most one flash per refusal, as in 0.1.39.

Mode changes and ordinary parking still complete for the session only. Made permanent while a mirror is on, they would store the mirror. Only the change that turns the mirror off is stored.
