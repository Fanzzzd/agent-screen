# A window another session holds goes to a new session only on the user's word

`place_window` used to refuse a window on another Agent Session's display, saying other agent sessions held it. One session needed WeChat while another session's display had it. It could only message the other session and ask it to let go, and neither agent could tell whether the user wanted that. Moving the window without the user is ruled out: from the window alone, Agent Screen can't tell whether the holder is still working in it.

So a request for such a window goes to the user. `place_window` for a window held by another session opens a Window Request, the same card and notification as for the user's own windows (ADR 0007). The card names the asking agent, the window and the holder: "Codex asks for WeChat. Claude Code · task B is using it." Hand Over moves the window to the asker's display as a Placement. Keep, labelled with the holder ("Keep with Claude Code"), leaves it where it is, and the asker's call fails with a reply naming the holder. The call waits up to 120 s by default, and a request nobody answers is withdrawn, as before.

A window is held by another session when it sits on that session's live Agent Display, or when it sits on the user's screen and a live display of that session records it or started its app. A window on a Review Display goes through the same request, whichever session stopped using it, and Hand Over takes it out of review. A Review Display's records hold nothing on the user's screen: the card would say the window waits for review while it sits in front of the user. The card says where the window is: on the holder's display, on a Review Display, or on the user's screen.

The user consents to the holder the card names, so Agent Screen looks again when they answer. If that holder still has the window, it moves. If the holder let it go meanwhile, as when its display ended and sent a Handover home, the window is the user's again and goes over as their Handover, with its return location. If another session has it by then, as when a second asker's card was open while the first one got the window, a new card names that session; the window never leaves the first asker on the strength of a card that named someone else. A card for one of the user's own windows looks again too: if another session took the window while the card was open, Hand Over moves nothing, and a new card names that session. Only one move of a window runs at a time. A display no session uses, such as one the user made from Peek, holds nothing this way; its windows still need the user to bring them out.

A Takeover of the holding display doesn't stop the request. The user is the one operating that display, so they can answer, and Hand Over moves the window even while the Takeover goes on.

A user's instruction in the conversation can stand for the card (ADR 0013), but only when it names the app. The session relays it as `user_instruction`. Agent Screen checks that the words contain the app's name, its owner name or its bundle id as whole words, ignoring case; a name in Chinese or Japanese, written without spaces, counts where it appears. "Check my email" doesn't name Mail, and "search" doesn't name Arc. Window titles don't count, since "open a new tab" would name a window titled New Tab. Words that name no app, such as "go ahead", open the card instead. A Window Authorization never covers another session's window: it is permission to take the user's windows, and this window is in another agent's work. Only the user's answer or their explicit words move it.

The holder learns what happened through the calls it already makes, without a push channel. Its display drops the window's record and remembers that the user gave it away. Every display of the holder's session remembers it, and an end_display that hands the session's apps to its next display hands the mark on too (ADR 0016), so no display of that session takes the window back as its stray. A drag the holder holds in the window lets go, and its queued Input Requests aimed at the window stop. A call that names the window on that display answers that the user gave the app to another agent session, rather than that no such window exists. The holder's next `list_windows`, screenshot or window state on that display says it once. The window no longer counts as the holder's stray, and its record no longer keeps it from the asker, even though the holder's session started the app.

A window the user handed over to the holder stays a Handover for the asker, with its original return location. When the asker's display ends, the window goes back to the user, never to the holder: the holder's claim on it was the user's gift, and the user now gave it elsewhere. Any other window becomes a Placement on the asker's display and stays for review when that display ends.

The same rule answers the reverse case. A holder that wants the window back calls `place_window` for it, which asks the user in the same way.
