# The app and its MCP server are one Rust binary

Agent Screen is being rewritten in Rust so it can later run on Windows and Linux. The UI uses GPUI (Zed's UI framework, pinned to a main-branch commit for AccessKit support and accessory launch), and the MCP server uses rmcp. `AgentScreen mcp` runs the MCP server from the app binary itself, so a client registers one path. A running MCP process can retain an older build after that binary is replaced. `get_diagnostics` compares the current MCP's compiled metadata with the responding app's read-only `getDiagnostics` reply. `AgentScreen diagnostics --json` collects the CLI and app identities; it cannot identify another MCP process. See [Reporting bugs](../REPORTING_BUGS.md). The server still only talks to the running app through the control socket, whose NDJSON protocol is the contract every platform implements.

This supersedes [ADR 0003](0003-upstream-effect-mcpserver.md): the TypeScript server in `packages/mcp` is gone. Its test scripts live on in `rust/tests/mcp` and drive the Rust server by default.

GPUI redraws the whole window from a display link on every frame, where the Swift app swapped a layer's contents. With the Viewer open on a display running at 60 fps, a release build of the Rust app uses 3.3% CPU against the Swift app's 1.6%; we accept that for one UI codebase across platforms. GPUI also clips live surfaces to rectangles only, so rounded corners are painted over them, and it ignores layer transforms, so the Viewer's open and close animate the native window frame instead of scaling a snapshot.
