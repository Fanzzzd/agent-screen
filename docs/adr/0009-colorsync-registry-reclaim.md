# Agent Screen reclaims ColorSync's display registry, through a root helper it runs with sudo

Every display change makes WindowServer (SkyLight's `CAWSManager::restore_color_preferences`) ask `colorsync.displayservices` for every online display's profile, wait 50 ms, and, when the answer is late, ask again every 5 s until one comes in time. Each display change starts another such loop. For each online display the service has colorsyncd read and parse the whole registry, `/Library/Caches/ColorSync/com.apple.colorsync.devices`, five times. The registry keeps a record for every display identity (vendor, product, serial) macOS has seen, never removed, and each record holds the display's name in the 39 languages of `/System/Library/Displays`, 97% of what gets parsed. An answer takes about online displays × records × 0.2 ms; trimmed to two or three languages, about a fifth of that.

Measured on one Mac: 84 records and 4 displays online, 66 to 91 ms, and loops piled up to hundreds of requests a minute (issue #26). 3 records plus 10 of Agent Screen's, trimmed, and 13 displays online, 23 ms.

Nothing a user process can do keeps the registry small. A name dictionary passed with `setDisplayInfoValue:forKey:` reaches WindowServer, but it takes the English name and writes it into all 39 languages. `ColorSyncUnregisterDevice` from a user process removes nothing, and the file is root's. Removing a record and trimming names need root.

## Decision

**A helper that runs as root only while it works.** The app bundle carries `agent-screen-colorsync`, a small binary with one job, `reclaim`. Setting it up copies it to `/Library/PrivilegedHelperTools/app.agentscreen.colorsync`, owned by root and not writable by the user, and adds `/etc/sudoers.d/agent-screen-colorsync-USER`, with one line: `USER ALL=(root) NOPASSWD: /Library/PrivilegedHelperTools/app.agentscreen.colorsync`. USER is the account that set it up, checked to be letters, digits, `_`, `.` and `-`; in the file name its dots become `_`, as sudo skips files in `sudoers.d` whose name has a dot. The file passes `visudo -c` before it is moved into place. The app runs `/usr/bin/sudo -n` with that path. No process stays running as root, and nothing the user's account can write runs as root: the copy in the bundle only serves the next setup. Each user of a Mac sets it up for themselves.

This is a standing grant: any process running as that user can run the helper as root. That is why the helper does one thing, takes no input but UUIDs, starts no other program, reads no environment, and only ever unregisters display records and rewrites one file. Apple's supported route, `SMAppService`, installs a launchd daemon, a root process the system keeps for good; we chose sudo to have none.

Setup takes the user's administrator password once, through macOS's own prompt, after the app says what it does and why: macOS rereads every display it has ever seen, in 39 languages, whenever displays change, and with many displays that makes the whole Mac stutter; Agent Screen can keep that list short with a small tool that only removes the records of displays that aren't connected. Declining leaves Agent Screen working with a lower display budget, and the menu offers the step again. The app counts the helper as set up only when `sudo -n` runs it and it prints its version: `sudo -l` passes for an administrator whom sudo would still ask for the password. The version is the helper's own, raised when what it does changes, so a release doesn't ask for the password again; when it differs, the app asks the same way. `Agent Screen colorsync remove` removes the user's sudoers file, and the helper once no user's is left, with the password.

**What reclaim keeps and removes.** For every display record (`Device.mntr.UUID`):

- A display that is online keeps its record.
- A record with anything besides `DeviceDescriptions` and `FactoryProfiles`, such as a profile someone chose, or a shape reclaim doesn't know, is kept.
- A record whose UUID the app passes with `--keep` is kept: the identities of Agent Screen's serials 1 to 16 of each instance, recorded when a display with them was online. Serials are reused (lowest free), so these come back, and a record macOS makes anew has all 39 names.
- Every other record is unregistered with `ColorSyncUnregisterDevice`. It holds only factory data, and macOS registers a display again when it connects. Profiles on disk stay.

Then, after reading the registry again to see what went, every record keeps its names only in English and the languages of the Mac's users, read from each home folder's global preferences; a record keeps at least one name. If the file isn't a dictionary of such records, reclaim writes nothing.

**Safe writes.** Reclaim takes an exclusive `flock` on `/var/run/app.agentscreen.colorsync.lock`, released when it exits, so two app instances never run it at once. It opens nothing through a symbolic link, and works only when the registry and its folder are root's and not writable by others. It writes nothing when nothing changes, so a run never makes work for the next. It writes the new registry to a fresh temporary file in the same folder, gives it the old one's owner and mode, checks that colorsyncd hasn't written the registry since it was read and left it alone for 2 s, and renames it over; otherwise it waits 2 s and reads again, up to three times, then stops for this run. Nothing locks colorsyncd out between that check and the rename. It writes in bursts, when displays change or someone picks a profile, so the 2 s keep a rewrite out of a burst; a profile picked in the instant between is the one case left. Unregistering checks the online displays again right before each record. Each `ColorSyncUnregisterDevice` call gets 5 s: SimpleDisplay saw it hang for good in its authorization step, and a run that hits that stops with an error. colorsyncd keeps the registry in memory too, so 2 s after a rewrite reclaim reads the file again and reports whether the rewrite was kept. The app kills a run that takes over 60 s. Reclaim never restarts colorsyncd: projects that kill it found it back and parsing again within seconds.

**When it runs.** The app runs reclaim 3 s after a display is created, 3 s after one is released, every 30 minutes, and 10 s after launch. Triggers that come while a run is due or running make one more run after it, never more. A run prints what it did as one JSON line, which the app writes to `displays.log`. Neither unregistering an offline display's record nor rewriting the registry changes the display configuration; this was checked by watching ColorSync's requests during runs.

**Display budget.** Before making a display, the app estimates an answer's time as online displays × (1 ms + records × c), c = 0.05 ms with the helper set up and 0.2 ms without, the record count from the last reclaim. Until the first run, 10 s after launch, it refuses nothing. Over 40 ms, it releases spares if that brings the estimate under, else refuses `create_display` and tells the agent to work on a display it has or end one. Twin retries for a taken unit number lease another serial instead of minting one, and a serial is free again only after its display has left the online list.

## Rejected

- Restarting colorsyncd after a rewrite, as HiDPIVirtualDisplay's cleanup does: the daemons come back within seconds (workshop-display-manager #128), and the rewrite doesn't need it.
- Cleaning `/Library/Preferences/com.apple.windowserver.displays.plist`, which also keeps a set of settings per combination of displays: cfprefsd caches it, a deletion sticks only with a WindowServer restart, which logs the user out, and it resets every display's remembered mode. Reused serials keep it from growing with each new display.

- A launchd daemon watching the registry: a root process installed for good, and running whenever macOS writes the file, for a job the app knows when to do.
- An administrator prompt at each run: periodic and post-change runs would prompt the user all day.
- `sudo` on the binary inside `/Applications/Agent Screen.app`: the user's account can replace it, so any process running as the user could run code as root.
- Deleting the registry file whole: it drops profiles users chose.
- Deleting the factory profiles of removed records: they cost nothing on a display change, and a wrong guess would delete system data.
- A name dictionary on the display descriptor: WindowServer writes the English name into all 39 languages anyway.
