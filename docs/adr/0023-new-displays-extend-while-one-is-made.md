# New displays extend while Agent Screen makes one

ADR 0020 turns a mirror off after macOS chose it, so the user's screen still flashed: 1.30 s at 16:20 on 2026-11-18 and 2.21 s at 21:38 on 2026-11-19 in loginwindow's log, from the main display going inactive at the new display's size to it being active at its own mode again. Most of that is WindowServer's. The display add takes about 0.9 s before `CGVirtualDisplay` returns, and WindowServer refuses a configuration completed meanwhile: `SLSCompleteDisplayConfigurationWithOption` loops on "Waiting for previous reconfig to complete" and then waits through the reconfiguration cycle. A watcher thread that sent the unmirror 0.22 s after the display was asked for, 0.66 s sooner than before, made the flash no shorter (the 2.21 s run).

The mirror itself is WindowServer's default for a set of displays with no stored arrangement. In SkyLight (macOS 26, `dyld_shared_cache_arm64e`), `WS::Displays::configuration_engine::apply_default_configuration` reads the session's TV-connect policy, the field `_XGetTVConnectDefaultPolicy` returns. With 1 it sends `config_command_mirror` for every display, with 0 it extends, and with 2 it starts presentation mode. `SLSSetTVConnectDefaultPolicy(cid, policy)` writes the `TVConnectPolicy` preference of `com.apple.windowserver.displays` for the current user and host, synchronizes it and sends it to WindowServer; `SLSGetTVConnectDefaultPolicy(cid, &policy)` reads it, and `SLSPackagesInitializeSessionPreferences` loads it at login. On the Mac of #220 it read 1 (`defaults -currentHost read com.apple.windowserver.displays TVConnectPolicy`).

Now `VirtualDisplay::create` sets the policy to 0 (`connect_policy::EXTEND`) before it asks for a display and sets the earlier value back when it returns (`display::extend_new_displays`). At 21:48 on 2026-11-19 the display came up extended at -1520,0, was parked 1.2 s later, the main display never went inactive, and the policy read 1 again 1.2 s after it was set to 0.

`connect-policy.json` in `~/Library/Application Support/Agent Screen/`, shared by all instances under `flock`, records the value to restore and the processes holding it (`connect_policy::PolicyHold`). The record is written and renamed in before the policy is set (`connect_policy::extend`), so a crash right after the set still leaves what to restore; a record that can't be written, or a lock that can't be taken, sets nothing. A set SkyLight doesn't confirm is held anyway, so the restore follows if it took. The last holder restores the value, only while the policy still reads 0, so a value other than 0 the user picks meanwhile stays; a 0 they pick within that second can't be told from Agent Screen's, and is replaced. A restore SkyLight refuses stays in the record. A holder is its pid, start time and login session: a pid alone is reused, after a restart often by a daemon that would hold the policy at 0 for good. A process holds once, however many of its changes overlap. A user whose policy is 0 already is left alone, and the file goes when nothing is held.

A holder that ends without restoring leaves the policy at 0 until the next display of any instance or the next start of any instance, which restore it. A panic that unwinds drops the hold; one that aborts restores it from the panic hook, which never waits for the lock, since the panic may have come while the process held it. An abort elsewhere, a kill or a hang leave it for the next display or start.

Other changes bring sets of displays too. Resizing a spare (`reuse_parked`) gives its display another serial's set, so it holds the policy the same way. Releasing an Agent Display while another stays leaves a set macOS may never have seen, such as the user's displays with the second display alone, so the release holds it until the display is gone, at most 3 s. Releasing the last one leaves the user's own set, arranged before. Sleep and wake keep the same displays, so the set's stored arrangement applies; WindowServer stores the arrangement of a set it applied its default to ("Saving configuration: session, permanent store" after "Applying default configuration"), so an extended set comes back extended. A monitor plugged in while an Agent Display is up brings a new set at the user's own policy, as without Agent Screen, with the Agent Display in it. None of these was measured.

While the policy is 0, a monitor the user plugs in extends where it would have mirrored. That lasts about a second per change. ADR 0020's unmirror stays as the fallback, for a SkyLight without these calls, a policy SkyLight won't set, and another app's display; `AGENTSCREEN_KEEP_CONNECT_POLICY=1` skips the policy, to test it. Setting the policy to 0 for good would end the mirror for other apps too; that is the user's choice, outside the app.
