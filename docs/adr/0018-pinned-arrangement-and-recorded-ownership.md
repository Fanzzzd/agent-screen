# Parked displays stay pinned while connected, and records decide virtual-display ownership

Agent Screen reuses the lowest free display serial per ADR 0009 so ColorSync does not accumulate stale device profiles. Sorting every virtual display by serial and reassigning slots from the anchor corner moved live displays whenever a lower serial came back or a spare joined. Moving a display's origin in WindowServer leaves windows at their previous global coordinates until Accessibility moves them, so one session's windows appeared inside whichever display took the old slot in issue #204.

`arrangement::plan` now pins every already-parked display of this instance at its verified global rect when that rect still satisfies the safety rules: right of the user's screens, no overlap, at most corner contact with user screens, and no lower than the rightmost user screen's top. Only unparked displays fill open grid slots. WindowServer refuses a display arrangement whose screens do not form one edge-or-corner-connected component with the user's screens, so when an ended display releases a bridge slot and leaves parked displays isolated, `arrangement::plan` unpins the unreachable displays and packs them back into connected slots.

When `Core::repark` runs, `display::configure` tucks newly seen displays away immediately without waiting on Accessibility writes from an earlier shift pass. `ReparkState` in `crates/model` serializes only shift planning and Accessibility frame writes under a monotonic generation counter, coalescing overlapping `ScreensChanged` notifications into a follow-up shift pass. Advancing the baseline atomically when shifts are planned prevents unrecorded sheets, dialogs and secondary windows from shifting twice across chain moves, and prevents an older pass from overwriting a newer baseline. Each shift pass uses a 0.25-second Accessibility timeout per window, skips remaining windows of any process that times out in that pass, caps total pass write time at 1 second, and returns failed targets to `ReparkState` for retry with a log line on first failure. Each origin move logs the old and new rects plus how many windows sat on each rect before shifting.

While windows sit on virtual Agent Displays, explicit records and geometry must stay aligned. `Displays` publishes its active owner table directly on every record or lifecycle mutation, and `arrangement::effective_agent_display` decides ownership across `list_windows`, `place_window`, `held_by`, window counting, spare evacuation, display removal and review dismissal:

1. If a window's geometry places it on a user screen, it belongs to no Agent Display, even if a display still holds an older record for it. Strays and windows the user took back stay on the user's screen.
2. While a window sits geometrically on any virtual Agent Display, an active `Launched`, `Found`, `Placed`, or `HandedOver` record in `Displays` overrides geometry, using one tie-break everywhere: the first live display holding a record, or else the first Review Display holding a record. When a recorded window has not yet arrived inside its owner display's bounds, `list_windows` marks it with `offDisplay: true` and omits coordinates so agents never click stale positions. Unrecorded windows on virtual displays follow geometry: intersecting the display with their center on no other display.

Input hit testing and Viewer title-bar drags intentionally check physical viewport geometry first. `Worker::hit` and `Worker::edge_hit` follow visual Z-order so Takeover input in the Viewer always hits the window visible to the user, while agent pointer tools check the topmost visible window at the target point and fail with the holder's label if another display owns that window. `can_grab_window` and `Grab::left_display` remain geometric because a Viewer title-bar drag operates on a window physically visible inside that display's viewport.

Spares report `has_windows: true` whenever either recorded ownership or physical viewport geometry finds a window on them, so `pick_spare` never hands a spare covered by a stray or an unshifted window to a new session. Spares evacuate unrecorded stray windows back to the user's screen with per-window exponential backoff when a window refuses the move.
