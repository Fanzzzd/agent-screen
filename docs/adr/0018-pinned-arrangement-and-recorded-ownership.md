# Parked displays stay pinned while connected, and records decide virtual-display ownership

Agent Screen reuses the lowest free display serial per ADR 0009 so ColorSync does not accumulate stale device profiles. Sorting every virtual display by serial and reassigning slots from the anchor corner moved live displays whenever a lower serial came back or a spare joined. Moving a display's origin in WindowServer leaves windows at their previous global coordinates until Accessibility moves them, so one session's windows appeared inside whichever display took the old slot in issue #204.

`arrangement::plan` now pins every already-parked display of this instance at its verified global rect when that rect still satisfies the safety rules: right of the user's screens, no overlap, at most corner contact with user screens, and no lower than the rightmost user screen's top. Only unparked displays fill open grid slots. WindowServer refuses a display arrangement whose screens do not form one edge-or-corner-connected component with the user's screens, so when an ended display releases a bridge slot and leaves parked displays isolated, `arrangement::plan` unpins the unreachable displays and packs them back into connected slots.

When any adopted display's parked origin changes, `Core::repark` translates the windows that belonged to its previous rect by the display delta, keeping their relative positions. `ReparkState` in `crates/model` runs one repark pass at a time under a monotonic generation counter and coalesces overlapping `ScreensChanged` notifications into a single follow-up pass after Accessibility frame writes finish. Advancing the baseline atomically when shifts are planned prevents unrecorded sheets, dialogs and secondary windows from shifting twice across chain moves, and prevents an older pass from overwriting a newer baseline. Each origin move logs the old and new rects plus how many windows sat on each rect before shifting.

While windows sit on virtual Agent Displays, explicit records and geometry must not disagree. `arrangement::effective_agent_display` is the single ownership rule used across window listing, `place_window`, `held_by`, input hit routing, spare counting, spare evacuation, display removal and review dismissal:

1. If a window's geometry places it on a user screen, it belongs to no Agent Display, even if a display still holds an older record for it. Strays and windows the user took back stay on the user's screen.
2. While a window sits geometrically on any virtual Agent Display, an active record in `Displays` overrides geometry, using one tie-break everywhere: the first live display holding a record, or else the first Review Display holding a record. Unrecorded windows on virtual displays follow geometry: intersecting the display with their center on no other display.

Spares holding unrecorded stray windows report `has_windows: true`, are never handed to a new session by `pick_spare`, and evacuate those windows back to the user's screen with per-window exponential backoff if a window refuses the move.
