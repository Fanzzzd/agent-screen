How it works. Each session gets a virtual display, and Agent Screen sends the agent's clicks and keys straight to the app's process in the background through SkyLight, a private macOS framework, so your cursor never moves. Read the virtual display architecture or ADR 0001.

Peek

Every Agent Display, one hover away.

Hover the menu bar icon to see every Agent Display live, or click it to keep Peek up. Open any of them in the Viewer to watch it full size.

Help Request and Takeover

It asks when it's stuck. You answer your way.

An agent stuck on a login or a captcha asks for you with a card under the menu bar icon and a notification, then waits. Did the step yourself? Press Continue. Reply sends it what you type, word for word. Take Over pauses it while you drive; press Let … Continue or tell the agent to continue in the conversation to hand the display back.

Handover

Hand a window over. Take it back.

Drag one of your windows onto the Viewer, or tell the agent to take it in the conversation. Press Take Back or ask the agent to return it, and the window goes back to where it was. An agent can also ask for a window; you answer Hand Over or Keep.

Web Preview

Watch from a browser tab.

create_display returns a link the agent can paste in chat, and Copy Web Link in Peek or the menu copies it too. The page shows the display live and read-only: it sends no clicks or keys, serves on 127.0.0.1 only, encodes nothing while no tab is open, and stops working when the display ends.

A display per agent session. Up to four when it needs them.

Run three agents at once and each gets its own screen. Subagents of one session share theirs. A session that needs two screens side by side can ask for more, up to four, each with its own label. Your windows stay put unless you give them to an agent. With many displays, turn on Smooth Display Changes in Settings.

  • Your browser, shared

    An agent can open a window in the browser you are typing in. Your keys stay in your window: while the agent's window opens, Agent Screen holds what you type, about a second in Dia, and then delivers it to your window in order. The agent's clicks and text reach its page through accessibility.

  • Menus and controls through accessibility

    Agents press buttons and pick menu items by name, so a button still gets pressed after its window moves or resizes. They choose an item in a standard Mac pop-up, or in a select on a page in a browser they started, without opening its menu. They step sliders that support it without dragging.

  • Input Queue

    When background input can't do a web drag or a click, the agent asks to use your pointer. A card shows what it wants to do, and nothing runs until you press Allow. Move the mouse, press a key or press Stop to take your pointer back.

  • Agent Pointer

    The Viewer and Peek draw an arrow where the agent last acted. Agent screenshots don't contain it.

  • Wait without polling

    An agent waits for a window or an element to change with wait_for_change, instead of sleeping and taking another screenshot. It gets back only what changed.

  • Recording

    An agent can record its display to an MP4, with the sound of its apps and a timeline of its actions and your Takeovers.

Install

  1. Install with Homebrew

    It needs macOS 15 or later.

    Terminal
    brew tap fanzzzd/agent-screenbrew trust fanzzzd/agent-screenbrew install --cask agent-screen

    Homebrew loads casks from a tap outside its own only once you trust it, which brew trust does.

    Or download the DMG from the latest release and drag Agent Screen into Applications. Agent Screen is signed with a Developer ID and notarized by Apple, so it opens like any downloaded app.

    Agent Screen updates itself. It downloads new versions in the background and installs them once no Agent Display is open, so an update never ends an agent's work.

  2. Open Agent Screen

    Agent Screen's Settings window asks for Screen & System Audio Recording and Accessibility. Both stay on this Mac.

  3. Connect your agents

    Press Connect… in Settings (right-click the menu bar icon and choose Settings…), or run:

    Terminal
    "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen" mcp install

    This registers the MCP server with Claude Code for all projects and adds it to ~/.codex/config.toml. It also installs the Agent Screen skill for both, which tells agents when a task needs a screen, so they use their display instead of open -a or AppleScript on yours. Each update of the app brings the skill up to date. For Cursor, Gemini CLI, Claude Desktop, VS Code, OpenCode or Zed, see the MCP client setup guide for copy-paste configs.

    For Cursor, Gemini CLI and other agents that read Agent Skills, add the skill with:

    Terminal
    npx skills add Fanzzzd/agent-screen -g

    In Claude Code you can install the skill as a plugin instead. See the Claude Code guide or the README for the command.

  4. Ask for something

    Start a new session and ask your agent something like:

    Use Agent Screen to open Calculator on your own display and work out 12 × 34.

Privacy

Agent Screen runs on your Mac and collects no telemetry. It checks GitHub for updates once a day, through Sparkle. The Web Preview listens on 127.0.0.1 only, so other machines can't open it. Agents reach Agent Screen through a socket only your user account can open, and a session can only see and drive its own display.

Limits

  • It uses private macOS APIs, so it can't be in the App Store, and a future macOS may break it.
  • Copy, paste and undo shortcuts do nothing in an app on an agent's display. Agents copy and paste through the accessibility tree instead.
  • Canvas apps and games that filter per-process events may ignore forwarded input.
  • A web drag with no background route waits in the Input Queue for your answer. Allow lets it use your pointer; Not Now declines it.

The README lists every known limit.

Frequently asked questions

Short answers on how Agent Screen works, which agents it supports, and where a virtual machine is a better fit.

How can Claude Code or Codex use my Mac without taking my mouse?

Agent Screen creates a virtual display per agent session with CGVirtualDisplay and sends clicks and keys straight to the target app process in the background through SkyLight, plus macOS Accessibility actions. Your real pointer, keyboard focus, and windows stay on your own screen. See how it works.

Which MCP clients work with Agent Screen?

Agent Screen works with any MCP client that runs a local stdio server. AgentScreen mcp install sets up Claude Code and Codex automatically, including the Agent Screen skill. Cursor, Gemini CLI, Claude Desktop, VS Code with Copilot, OpenCode, and Zed connect with the same stdio command. View all client configs.

How is Agent Screen different from a macOS virtual machine or built-in computer use?

Built-in computer use drives your real pointer and keyboard, so you cannot work while the agent works. A virtual machine isolates the agent, but requires setting up apps and logins again inside each VM. Agent Screen uses the real Mac apps and logins you already have on a separate virtual display, with one-click Takeover from the menu bar, though it is not a security sandbox.

What happens when an AI agent hits a login screen or captcha?

The agent calls request_help, which drops a Help Card under the menu bar icon with the display image and reason, and pauses. You can press Take Over to sign in yourself and hand control back, press Continue if you handled it elsewhere, send a Reply, or give the agent one of your windows.

Is Agent Screen private, and is it a security sandbox?

Agent Screen runs locally on your Mac, collects no telemetry, and checks GitHub once a day for updates via Sparkle. Web Preview listens on 127.0.0.1 only, and agents connect over a user-only local socket. It is not a security sandbox: the agent drives your real apps with your accounts. Use a VM if you need OS isolation.

Why does Agent Screen require macOS 15 or later and use private APIs?

Sending clicks and keys to background apps on a virtual display without warping the user's cursor relies on private macOS SkyLight APIs and CGVirtualDisplay. Because of those private APIs, Agent Screen cannot be listed on the Mac App Store and a future macOS release may break it. The app is Developer ID signed, notarized by Apple, and MIT licensed.
