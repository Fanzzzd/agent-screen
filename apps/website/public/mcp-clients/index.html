Agent Screen / MCP clients

MCP computer use on macOS in the background.

Agent Screen ships a local stdio Model Context Protocol server inside the macOS app bundle. Any MCP client can open Mac apps, read the accessibility tree, click, type, and record video on its own virtual display without API keys or network calls.

Local stdio transport No API keys or cloud proxy Command: AgentScreen mcp

Automatic setup (Claude Code and Codex)

First install Agent Screen via Homebrew (brew tap fanzzzd/agent-screen && brew trust fanzzzd/agent-screen && brew install --cask agent-screen) or the DMG, open it, and allow Screen Recording and Accessibility in Settings.

Press Connect… in Settings or run:

Claude Code + Codex
"/Applications/Agent Screen.app/Contents/MacOS/AgentScreen" mcp install

In v0.1.41, if Agent Screen is not already open, the agent's first tool call starts it automatically (the upcoming release on main starts it as soon as the client connects). Start a new session or restart your client after editing its MCP configuration.

Configuration by MCP client

Every client runs the same local binary (/Applications/Agent Screen.app/Contents/MacOS/AgentScreen) with the single argument mcp. No environment variables or tokens are required. See docs/clients.md on GitHub for the latest notes.

Claude Code

Configured automatically by AgentScreen mcp install, or add manually for all projects:

Terminal
claude mcp add --scope user agent-screen -- "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen" mcp

Codex (CLI, IDE extension, and desktop app)

All three share ~/.codex/config.toml (also written by AgentScreen mcp install):

~/.codex/config.toml
[mcp_servers.agent-screen]
command = "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen"
args = ["mcp"]

Cursor (editor and CLI)

Add to ~/.cursor/mcp.json globally or .cursor/mcp.json per project. In Cursor's CLI, enable a project server with cursor-agent mcp enable agent-screen.

~/.cursor/mcp.json
{
  "mcpServers": {
    "agent-screen": {
      "command": "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen",
      "args": ["mcp"]
    }
  }
}

Gemini CLI and Claude Desktop

Use the same mcpServers JSON block above in ~/.gemini/settings.json (or .gemini/settings.json) for Gemini CLI, or in ~/Library/Application Support/Claude/claude_desktop_config.json for Claude Desktop (quit and reopen Claude Desktop afterward).

VS Code with Copilot

Add to ~/.copilot/mcp-config.json or workspace .mcp.json with "type": "stdio":

.mcp.json
{
  "mcpServers": {
    "agent-screen": {
      "type": "stdio",
      "command": "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen",
      "args": ["mcp"]
    }
  }
}

OpenCode

Add to project or global opencode.jsonc:

opencode.jsonc
{
  "mcp": {
    "servers": {
      "agent-screen": {
        "type": "local",
        "command": ["/Applications/Agent Screen.app/Contents/MacOS/AgentScreen", "mcp"]
      }
    }
  }
}

Zed

Add under context_servers in Zed's settings.json:

settings.json
{
  "context_servers": {
    "agent-screen": {
      "command": "/Applications/Agent Screen.app/Contents/MacOS/AgentScreen",
      "args": ["mcp"],
      "env": {}
    }
  }
}

Install the Agent Screen skill

For Cursor, Gemini CLI, and other agents that read Agent Skills, install the companion skill so the agent reaches for its virtual display automatically instead of running open -a on your main screen:

Agent Skills installer
npx skills add Fanzzzd/agent-screen -g

For agents without a skill loader, copy docs/agents/AGENTS.md into your project's AGENTS.md or CLAUDE.md.

How Agent Screen keeps client sessions apart

Each Agent Session owns its displays, Window Authorization, and Help Requests. In v0.1.41, Agent Screen identifies a tool call's session from the first matching source:

  1. Claude Code session variable: Claude Code passes CLAUDE_CODE_SESSION_ID to stdio servers. (The upcoming release on main checks Codex metadata first and scopes CLAUDE_CODE_SESSION_ID strictly to clients identifying as claude-code, so a child client launched from a Claude Code shell gets its own session.)
  2. Codex per-call metadata: Codex sends x-codex-turn-metadata on each tool call, so multiple Codex conversations sharing one server process stay on separate displays.
  3. Per-process connection: Clients that send no session hint (such as Cursor, Gemini CLI, OpenCode, Zed, VS Code, and Claude Desktop) get one session per started AgentScreen mcp process. Note that Claude Desktop launches one MCP server process at startup, so its conversations share that session.

When a client restarts or closes its MCP process, Agent Screen waits a 2-second grace period so reconnecting clients can rebind their displays before closing empty displays or marking remaining windows for review.

MCP tools reference

Tools Purpose
create_display, end_display Create or reuse the session's Agent Display (up to four with new: true), returning a display handle and a read-only local preview_url.
launch_app, place_window, list_windows Open apps by name, bundle ID, or .app path onto the display, list windows or strays, and set exact window frames.
computer Anthropic-style display actions (click, move, drag, scroll, type, key, screenshot). Every action except wait and cursor_position returns a screenshot.
get_window_state, act_on_element Read one window's screenshot and numbered macOS accessibility tree; press buttons, choose menu items, set or insert text, and read text by element number.
wait_for_change Wait until a window or element subtree changes, or a matching role/text appears or disappears, returning only the delta instead of polling screenshots.
request_help, wait_for_control, request_control Ask the user to step in for logins or captchas, wait out a Takeover, or request control back.
input_queue Inspect, wait for, withdraw, or finish user-approved pointer operations when background input cannot run a drag or click.
window_access, set_disposition Manage session window authorization, return handed-over windows, and mark whether windows should be kept or closed at review.
record_display, get_diagnostics Record an Agent Display to MP4 in ~/Movies/Agent Screen with app audio and action timeline, or collect build diagnostics.
