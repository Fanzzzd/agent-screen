Agents can choose an item in a pop-up button or a web page's select, such as a country or birth date field, with `act_on_element set_value` and the item's exact title (#79). No menu opens, so your keyboard stays yours. In a Chromium browser or Electron app the agent started with `launch_app`, a select in the page is chosen directly, with one change event. Elsewhere Agent Screen types into the closed control only where a typed key can't open its menu: an AppKit pop-up button or a Chromium page's select, and only once the control has the app's focus. It never types a space. For a title with one, it types the part before the space only when that alone reaches the item. Keys go only to that app, and stop if another window or field takes the keys, as when the page moves on to the next field after a choice, if the window leaves the display, or if a key would come too late. If Agent Screen can't tell what kind of control it is, it sends nothing. A Safari or other WebKit page's select, a button that opens a menu, a title whose start other items share, and a title starting with a repeated key such as "11" or "1100" in a web select get no key at all, and the call says why and suggests asking you. If the control ends up showing another item, the call fails and names it. A control that already shows the title gets no keys. A combo box gets its value and then a confirmation, and the call fails if the app rejects it. A web page's combobox has nothing to confirm, so the call says the text is set but no option is chosen. When you take over the display, the choice stops before the next key and says what the control shows. A text field that reports an error but shows the new value now counts as set.
